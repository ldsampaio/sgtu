# 03 — Modelo de dados

## Propriedade de schema (regra dura)

- `auth` é do **saga**. O Prisma do SGTU só lê `AuthUser`/`AuthProfile` (`@@schema("auth")`).
  Nenhuma migration do SGTU cria ou altera tabela em `auth`.
- `sgtu` é do SGTU. Toda migration muda **apenas** `sgtu.*`.

Migrations são escritas à mão e aplicadas com `npx prisma migrate deploy` — nunca
`migrate dev` (com multiSchema o Prisma geraria DDL para `auth`).

## Tabelas `sgtu`

| Tabela | O que guarda |
|---|---|
| `user_roles` | papel por sistema (`ADMIN`\|`USUARIO`), `status` |
| `tickets` | ticket; `numero` é `GENERATED BY DEFAULT AS IDENTITY` (rótulo `TKT-000123`, nunca reutilizado) |
| `ticket_mensagens` | mensagens; `interna` é nota de admin, nunca exibida ao autor |
| `ticket_eventos` | trilha de auditoria (quem mudou o quê) |
| `ticket_anexos` | anexos; `caminho` é hash no disco, nunca o nome enviado |
| `telemetry_events` | eventos de uso crus, 90 dias |

Nada de credencial: não há coluna de senha, de token, de cookie, de `sid`, de IP, de
user-agent ou de fingerprint. Isso é minimização **estrutural** — as colunas não existem,
não é uma regra de código que alguém pode esquecer.

## `vuso_diario`

View materializada criada em migration SQL (`0004_dashboard_agregado`), **não** model do
Prisma — o Prisma não modela view materializada, então o dashboard lê via `$queryRaw`.
Agregado **permanente**: nunca expurgado. Sem dado pessoal — `user_id` entra só como
`DISTINCT` na agregação e não existe como coluna da view.

Colunas: `dia`, `sistema`, `eventos`, `usuarios`, `erros_401`, `erros_503`. Os dois contadores
de erro existem separados porque o spec do dashboard exige 401 e 503 como linhas separadas por
sistema — juntar os dois é errado.

## Armadilhas verificadas

- FK condicional (`to_regclass('auth.users') IS NOT NULL`) para o `migrate deploy` funcionar
  em banco limpo de CI antes do fixture; a ordem é deploy → fixture.
- `_prisma_migrations.id` precisa ser `varchar(36)` (tipo canônico do Prisma). Com `uuid` o
  deploy falha com "Failed to extract `id` from `_prisma_migrations` row".
- Dev usa o Postgres compartilhado da plataforma (`sgrf-db-1`, user/db `sgrd`, schemas
  `auth/sgoa/sgrf/sgtu`) — o mesmo banco, não um banco por sistema.
